# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Web survivor-like game ("山海吞噬录") — Chinese-language UI. TypeScript (strict) + Vite + PixiJS v8 (WebGL renderer, explicitly preferred over WebGPU). This is the productionized rewrite of the single-file Canvas2D demo preserved at `legacy/gemini-code-1791969672274.html`; the legacy file is the reference for exact game feel and numbers, and all ported formulas match it 1:1 (deliberate deviations are annotated in `src/config/balance.ts`).

## Commands

```bash
npm run dev          # Vite dev server (host:true → works as localhost, 127.0.0.1 and over LAN for phone testing)
npm run build        # tsc --noEmit && vite build (dist/, base './' for static hosting)
npm run preview      # serve the production build locally
npm run typecheck    # tsc --noEmit only
npm test             # vitest run (all tests); npm run test:watch for watch mode
npx vitest run tests/sim.test.ts   # single test file
npm run smoke        # headless-Chromium UI smoke test → screenshots in tools/screenshots/
npm run shots        # 美术审查截图（封面/图鉴/进化卡/战斗特效/压测/暂停/本局构筑）
npm run fonts        # 重新生成自托管字体子集（新增中文文案后必须执行）
node tools/extract-data.mjs        # regenerate src/config/{genes,forms,organs,passives}.ts from legacy/
```

`npm run smoke` needs Chromium once: `npx playwright install chromium`. To verify an already-running server (e.g. the instance the user has open) instead of spawning one, pass the URL: `SMOKE_URL=http://127.0.0.1:5173/ node tools/smoke.mjs`.

Two test layers, and they catch different things:
- **Vitest (`tests/`, Node environment)** — pure logic and the whole simulation. Must not import anything touching DOM or Pixi (that means never `src/render/*` or `src/ui/*`); `tests/sim.test.ts` runs `updateWorld` headlessly, and `quietWorld()` disables the spawner/boss for determinism. This layer cannot catch UI/CSS/rendering bugs.
- **Playwright smoke (`tools/smoke.mjs`)** — real browser: modal/state flows (pause, codex tabs, forced-choice interception), HUD button clickability at desktop and narrow viewports, stress FPS, console errors. Extend this whenever you touch UI wiring; it asserts via `window.__game` (dev-only handle) plus DOM visibility. Read the screenshots it writes — they are the fastest way to spot rendering regressions.

There is no lint setup yet.

## Architecture

Data flows one way: `main.ts` → `Game` (orchestrator in `src/game/game.ts`) → `FixedLoop` steps `updateWorld` at 60Hz → world events (`world.events.*`) drive UI modals; the Pixi scene reads the world every render frame. All UI text, comments, and names are zh-CN — match that.

Boot contract (`Game.init`) is deliberately fault-tolerant and order-sensitive: font loading is raced against a 3s timeout, the **ESC listener is registered before any wiring**, and button wiring runs through a `[name, fn]` step list where a throw is logged and skipped rather than aborting init. This exists because a single missing DOM node used to abort init midway — which silently killed the pause button *and* ESC while leaving the start button working, producing a "nothing responds" report that looked like a key-listener bug. Keep new wiring inside those steps (or use `byIdOpt`/`on` in `src/ui/modals.ts`) so one absent node can never take down unrelated features. `main.ts` additionally installs an on-screen fatal-error overlay plus a global `error` handler, so runtime failures surface in the page instead of only in the console.

**`src/config/`** — pure data. The four tables (9 gene tags, 37 forms across 5 stages, 12 active organs, 12 passive genes) are generated by `tools/extract-data.mjs` from the legacy demo (with count validation); edit the generated files directly for number tweaks. `balance.ts` centralizes the tuning constants that differ from legacy (enemy cap 500 vs 115, gem/particle caps, separation toggle, stress count).

**`src/core/`** — engine-agnostic utilities:
- `loop.ts` — fixed timestep (1/60), max 4 catch-up steps per frame, drops backlog after a tab-switch stall.
- `spatial.ts` — `SpatialGrid`: uniform grid over TypedArray linked lists, `build()` is allocation-free. **Contract:** rebuild once per simulation step; `queryCircle()` returns a shared internal buffer that must be consumed immediately and never nested (a query inside a query loop corrupts it). All queries are coarse — callers do exact distance checks.
- `pool.ts` — `Pool<T>` + `decayAndCompact` (in-place life-decay compaction that releases to the pool; never use `Array.filter` for per-frame entity arrays).

**`src/game/`**:
- `types.ts` — every hot entity (enemies, projectiles, zones, gems, …) is a pooled plain object; `World` holds all entity arrays plus `pools`, `grid`, `events`, and `view` (viewport size, written by the renderer each frame, read by spawn logic).
- `world.ts` — `createWorld()` / `resetWorld()` (releases all entities back to pools; player is recreated). 本局配置（`difficulty`/`startOrganId`/`bloodline`）由 `Game.startNewGame` 在 reset **之前**设置，`resetWorld` 保留它们；`player.meta` 在 reset 之后由 `metaBonuses(save)` 注入。
- `spawn.ts` — 遭遇系统的核心：`WILD_TYPES`（6 种野生怪 **带行为**）、精英（`spawnElites` + 词缀 applyAffix）、**波次导演**（`generateRunPlan` 生成每局随机剧本、`updateDirector` 推进段位与随机事件、`triggerEvent`）、Boss/宝物妖、难度缩放。`BOSS_TEXTURE_INDEX = WILD_TYPES.length`（动态，加类型自动顺延）。
- `update.ts` — `updateWorld(world, dt, move)`：整个模拟步。**顺序是承重的**（武器 → 环绕体 → 流星 → 龙卷 → 法阵 → 投射物 → 刷怪（导演在内）→ 敌人行为循环 → 敌方弹幕 → **重建网格** → 治疗光环 → 群体分离 → 经验球 → 衰减）。要点：
  - 敌人移动由 `behavior` 分支驱动（追击/远程/冲锋状态机/光环/逃跑），冲锋的位移直接施加在状态机里（`moved` 标记跳过通用位移）。
  - `damagePlayer(world, raw)` 是玩家唯一受伤入口（接触/弹幕/爆裂），返回 true 表示死亡，调用方必须立即 `return`。
  - `handleEnemyDeath` 负责击杀计数、分裂、爆裂、掉落、Boss 计数与 `checkVictory`。
  - **治疗光环在网格重建之后运行**（`applyBufferAuras`），因为敌人循环期间会 splice 数组、索引会失效——任何新的"邻居效果"都要跟这个模式走。
  - `checkVictory`：击败 `victoryBosses` 或存活 `victoryTime` 即通关；`world.endless` 会阻止再次触发。

**`src/combat/`**:
- `weapons.ts` — the 12-organ switch (`updateWeapons`) + `updateOrbitingSpikes`. Every case ports the legacy numbers exactly; the `spore` case is the `default` (unknown organ ids silently use it).
- `effects.ts` — `spawnXxx` functions and `hitCircle` (grid query + exact check; `addEnemyRadius` / `angleCenter` flags reproduce each skill's original hit rule).
- `damage.ts` — crit (spirit passive), lifesteal (fang), boss knockback resistance, floating text/particle caps.

**`src/progression/`** — `genes.ts` (`recalculateStatsAndGenes`: form tags ×2, organ `level + 3 if evolved`, passive `level × 2`; derived stats; fires `onStatsChanged`), `choices.ts` (`generateUpgradeChoices` + `matchTop3FormsForStage`), `leveling.ts` (exp curve `×1.25+12`; levels 5/10/15/20 fire `onStageEvolution`, others `onLevelUp`), `summary.ts` (`summarizeBuild`: pure derived-stat + synergy-status computation powering the in-run build panel; keep its formulas in sync with `updateWeapons`/`recalculateStatsAndGenes`).

**`src/render/`** — 像素美术管线。三条规则先记住：
1. **一切绘制都在"艺术像素"(texel)坐标系里，整数坐标 + 硬边矩形**（`pixel.ts` 的 `pxRect/pxEllipse/pxLine/pxTri`），绝不使用贝塞尔曲线或柔和渐变——那会立刻破坏像素感。
2. **换算规则**：每张贴图声明自己的艺术半径 `texelR`，运行时 `sprite.scale = 目标世界半径 / texelR`；贴图的艺术半径都刻意取 `世界半径 / TEXEL`（`TEXEL = 3` 世界像素/像素），使全屏颗粒大小一致。改 `TEXEL` 会整体改变颗粒粗细。
3. **采样**：`antialias: false` + 贴图 `scaleMode = 'nearest'` + CSS `image-rendering: pixelated`；精灵/震屏位置取整，避免半像素糊边。

- `pixel.ts` — 像素图元与配色工具：`pxRect/pxEllipse/pxRing/pxLine/pxTri/pxDitherEllipse`（棋盘抖动＝像素风的半透明）、`shade()`（明暗阶梯，用于描边与受光面）、`bodyFill()`（深色形态提亮，否则会变成一团黑影）、`texelRadius()`。
- `painter.ts` — **所有异兽/小怪美术的唯一来源**：7 种体型（quadruped/drake/spider/serpent/bird/turtle/deity）+ 角/翼/尾/头部件，全部用像素图元绘制。因为美术是程序化的，改图元即同时升级 角色/敌人/图鉴缩略图/进化卡/封面预览。只在浏览器运行。
- `textures.ts` — 启动时把美术烘焙成**低分辨率**贴图（小画布）：小怪 8 帧行走 + 白色受击帧 + Boss 配色、Boss 警示环、冰剑/四叶风刃/鬼火、爪击月牙、骨剑、粒子与经验球、像素网格与装饰环。法阵类**不烘焙**（半径跨度 50~500，烘焙会破坏颗粒一致性），由 `scene.ts` 用 Graphics + 坐标量化绘制。
- `scene.ts` — Pixi 图层 + `SpritePool`/`GraphicsPool`/`TextPool`（begin/acquire/end）。高频视觉是精灵，低频动画特效（天雷/激光/触须/流星/龙卷/法阵）是 Graphics，且**顶点量化到 TEXEL 网格 + 方头线帽**（`q()` 与 `steppedCirclePath()`），否则线条会过于平滑而不像素。特效统一 `blendMode = 'add'`。玩家真身每帧绘制到小画布（约 26~44 艺术像素）后 `CanvasSource.update()` 上传。

**`src/meta/`** — 局外成长。`save.ts`：`MetaSave` 结构（精华/难度/解锁/属性节点/图鉴点亮）、`loadMeta`/`persistMeta`（localStorage，不可用时自动降级内存，Node 可测）、`computeEssence` + `settleRun`（结算入账与难度解锁）、`metaBonuses`（节点加成，注入 `player.meta`）、`recordFormUse`/`recordSynergy`（图鉴点亮）。改结构要升 `SAVE_VERSION` 并在 `normalize()` 里容忍旧档缺字段。

**`src/ui/meta.ts`** — 祭坛解锁树（购买交互）、开局准备（择器降世：起始器官 + 血脉祝福）、**胜负统一结算弹窗**、随机事件横幅。`src/ui/meta.ts` 从 `modals.ts` 导入 `openPauseMenu`/`showHint`，`modals.ts` 只从 `meta/save.ts` 读数据——保持这个方向，别让 modals 反向 import meta.ts（会成环）。

**`src/ui/`** — DOM overlay，永不进渲染热路径。`hud.ts`（结构刷新走 `onStatsChanged`，数值刷新带变更守卫）、`modals.ts`（升级/进化/图鉴/暂停 + 试炼台；打开任何弹窗都会置 `PAUSED`）、`buildPanel.ts`（本局构筑页签，渲染 `summarizeBuild`）、`previews.ts`（DOM 画布预览）、`icons.ts`（器官 SVG）。结算已迁至 `ui/meta.ts` 的 `openSettlement`。

Modal state machine (in `modals.ts` + `Game.togglePause`): `ESC` pauses during play, resumes when the pause menu is open, and closes the codex otherwise — it deliberately does nothing while the upgrade/evolution modals are open (those are forced choices). The codex is one modal with three tabs (`build` / `forms` / `synergies`); `openCodexFromPause` sets a flag so closing it returns to the pause menu instead of resuming the run. `Game.backToTitle()` resets the world and returns to the start modal.

## Performance invariants (do not break)

- **No per-frame allocation in hot paths.** Spawn via `world.pools.*`, remove via `decayAndCompact`/sweep-to-pool. Never `.filter()`/`.map()` entity arrays per frame, never create vectors in render loops.
- **Never nest `SpatialGrid.queryCircle` calls** and never hold its returned buffer.
- **Keep high-count visuals as pooled sprites.** New effects should be baked into `textures.ts` if they can appear in the hundreds; Graphics is only acceptable for bounded counts (single/double digits per frame).
- **No `shadowBlur`/filters on hot paths** — glow is `blendMode: 'add'`.
- **DOM is not part of the 60fps loop**: HUD writes are guarded; modals pause the simulation.
- WebGL renderer is pinned (`preference: 'webgl'`); WebGPU is an upgrade path, not the default (browser support still uneven in 2026).

## Gotchas when extending

- **Adding an organ** takes four edits: an `ACTIVE_ORGANS` entry in `src/config/organs.ts`, an SVG icon in `ui/icons.ts`, a `case` in `updateWeapons` (else it falls into the `spore` default), and a matching passive id in `src/config/passives.ts` for its `pairPassive`.
- **Adding a beast form**: reuse existing `archetype`/`horns`/`wings`/`tailStyle` values or extend `painter.ts`; keep `ALL_FORMS.stage2..stage5` at 9 entries each (the evolution UI is "9 choose 3"). Stage arrays and the codex iterate them directly.
- **Adding an enemy visual**: extend `WILD_TYPES` (with a matching `bakeWildSet` call in `textures.ts`) and keep `Enemy.typeIndex` in sync — the renderer indexes baked frames by it.
- The simulation deliberately keeps legacy quirks (e.g. `dealDamage` overkills corpses, healing choice text says +12% attack but applies `taotieStacks += 25`). Don't "fix" these silently — they define the game's balance; call them out if they must change.
- **新的"邻居效果"系统必须走 `applyBufferAuras` 的模式**：敌人循环里会 splice 数组、网格索引失效，因此这类系统要放在**网格重建之后**独立遍历；绝不能在敌人循环内部调用 `grid.queryCircle`。
- **新增敌人行为**：扩展 `EnemyBehavior` 联合类型 → 在 `update.ts` 的行为 switch 里加分支（保持每帧 O(1)，不要分配）→ 挂到某个 `WILD_TYPE`（或由事件用 `initEnemy` 的 `behavior` 覆盖）。**新增精英词缀**：`EliteAffix` + `applyAffix` + `AFFIX_NAMES`/`AFFIX_COLORS`（颜色会自动用于精英环与图鉴文案）。
- **局外存档改结构**要升 `SAVE_VERSION` 并在 `save.ts` 的 `normalize()` 里给缺字段兜底；`tests/meta.test.ts` 已覆盖往返/旧档/损坏档。结算每局只入账一次（`Game.runSettled`），无尽续玩不会重复结算。
- `tests/sim.test.ts` uses a `quietWorld()` helper (disables spawner/boss) — first step otherwise spawns enemies because `spawnTimer` starts at 0. `tests/encounters.test.ts` 的 `quietWorld()` 还会关掉随机事件计时（`director.eventTimer`）以保证可控。
- **Custom CSS must stay inside `@layer components` in `src/styles.css`.** Tailwind v4 utilities live in a cascade layer, and *unlayered* rules beat layered ones — a custom class setting `display` outside the layer silently defeats `.hidden` (this actually broke the hint toast once). Putting custom classes in the layer keeps utilities able to override them.
- **New HUD buttons need `pointer-events-auto`.** `#hud` is `pointer-events-none` so the HUD doesn't eat mouse input; without the class a button renders fine but never receives clicks.
- **UI keeps square corners and hard shadows on purpose** (`rounded-none` everywhere, no `backdrop-blur`, stepped gradients via `repeating-linear-gradient` hard stops). Adding a soft shadow/blur/rounded corner will visibly break the pixel style.
- **Preview canvases are pixel-resolution and upscaled by CSS** (`image-rendering: pixelated`). When adding one: give it an explicit CSS size and let the draw function set `width/height` to the tiny texel size — and remember coordinates inside those canvases are already texels, so don't divide by `TEXEL` again.
- `npm run shots` captures art-review screenshots (start/hero, codex, evolution cards, combat FX, horde, pause, build panel). Read them after any change to `painter.ts`/`textures.ts`/CSS — most art regressions are only visible there.
- The top HUD row must keep `flex-wrap` — `body` is `overflow: hidden`, so buttons pushed out of the viewport by a narrow window become completely unreachable rather than scrollable.
- `npm run smoke` drives a real headless Chromium (`--use-angle=swiftshader`) through the key flows and writes screenshots to `tools/screenshots/`; use it after touching modals/UI state, and read the screenshots to sanity-check rendering. **Playwright is intentionally NOT a project dependency** (it's a local test tool only, to keep CI/deploy installs light) — the tools dynamically import it and print the install command if missing. They load pages with `?debug=1`, which is the production-safe switch that exposes `window.__game` (dev builds expose it by default). Verify a *production* build by running `npm run build`, serving `dist/` (e.g. `npx vite preview`), then `SMOKE_URL=<url> node tools/smoke.mjs` — the same suite runs against the artifact that gets deployed to Cloudflare Pages.
- **Fonts are self-hosted as generated subsets** — `src/assets/fonts/*.woff2` + `src/assets/fonts.css` come from `npm run fonts` (`tools/fonts.mjs`), which scans `index.html` + `src/**` for every CJK/ASCII char used and fetches matching woff2 subsets from Google Fonts, emitting one `@font-face` per chunk with its own `unicode-range`. **After adding any new Chinese text (form/organ/skill names in the data tables, UI copy), re-run `npm run fonts`** or the new glyphs silently fall back to system fonts. Never hand-edit the generated CSS; the smoke suite asserts fonts load locally and that zero requests hit Google's font CDNs.
- `legacy/` is read-only reference; `tools/extract-data.mjs` reads it, so don't rename or delete that file.
